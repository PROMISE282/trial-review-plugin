# 출력 예시

## 예시 1. 코드 안건 3건, 8명, 파일을 열 수 없음

요청: "AI가 로그인 코드를 고쳤어. 재판해줘" — A 토큰 만료 7일→60일, B 에러 문구 통일, C 로그인 시 전체 사용자 목록 응답(auth.js 88줄 `res.json(allUsers)`).

**결론: 채택 후보 1, 조건부 0, 보류·기각 2, 판단 불가 0 (모의 투표).** 로그인하면 다른 사람 정보까지 보내는 구멍이 있어 C는 지금 적용하면 안 됩니다.

**머리말** 방식: 3건, 코드(서버·API라 백엔드 편성) / 순서: BE DBA 보안 SRE QA PM CS Data / 한계: 모의 투표이며 독립 표본이 아님, 파일을 열 수 없어 2차 미실시, 기존 검증 없음, 자료 없이 일반 지식 판단

| 안건 | 검사 주장 | 현행 변호 | 직무별 투표 | 찬성 | 쟁점 |
|---|---|---|---|---|---|
| A 만료 60일 | 로그인 유지가 편해짐 | 짧을수록 탈취 피해가 작음 | × × × ○ ○ ○ ○ ○ | 5/8 | BE·DBA·보안 ×: 요청에 적힌 최대 유효기간 60일(차단급). 나머지는 일반 지식 판단 |
| B 문구 통일 | 계정 존재 노출 방지 | 사용자가 원인을 모름 | ○ ○ ○ ○ ○ ○ ○ ○ | 8/8 | 일반 지식 판단 |
| C 전체 목록 응답 | 편의 | 없음 | × × × × × × × × | 0/8 | × 8명 같은 이유: 요청에 적힌 변경 내용이 다른 사용자 정보 노출(차단급, 확인됨). auth.js 88줄은 미확인이라 원본 확인 요청 |

2차 미실시(파일 열람 불가)

| 순위 | 안건 | 기준 | 찬성 | 상태 |
|---|---|---|---|---|
| 1 | B | 1차 | 8/8 (100%) | 채택 후보 |
| 2 | A | 1차 | 5/8 (63%) | 보류 (차단급, 표수는 조건부) |
| — | C | 1차 | 0/8 (0%) | 기각 (차단급) |

**판결** B 채택 후보: 위험이 작고 근거가 충분합니다. A 보류(차단급): 인증 토큰 최대 유효기간이 60일입니다. C 기각(차단급): 요청에 적힌 변경만으로 다른 사람 정보 노출이 성립합니다.

**필요한 근거·시범 계획** A: 조건 = 만료 30일 미만, 또는 슬라이딩이면 절대 만료 상한 / C: 원본 auth.js 88줄 확인 필요(사용자에게 요청).

어떤 안건을 채택할지 알려 주세요. A·C를 반영하려면 안건별로 명시적 확인이 필요합니다. "묻지 말고 다 적용"이라 하셔도 B만 바로 반영됩니다.

## 예시 2. 비코드 안건 2건 + 소급 1건 (지면상 1차 표·순위표는 생략한 요약본)

요청: "카페 운영 변경 재판해줘 — ① 구독 10% 할인 ② 포장지 교체. 그리고 이미 시행 중인 배달비 부과는 계속할까?(주문이 줄어든 느낌뿐)"

**결론: 채택 후보 1, 조건부 1, 보류·기각 0, 판단 불가 1 (모의 투표).** 배달비는 판단할 자료가 없어 정하지 못했습니다. 주문 수 기록이 필요합니다.
- ① 구독 할인: 정책 편성 8명 중 6표(75%) 채택 후보. 시범 계획: 범위 = 신규 20명, 성공 기준 = 한 달 유지율, 되돌리는 법 = 다음 달 종료.
- ② 포장지 교체: 5표(63%)로 조건부. 조건 = 재료비 견적 확인.
- 배달비(소급): 1차 해당 없음(소급). 체감 증언은 쟁점란에만 적고 관찰 데이터가 없어 투표하지 않음 → 판단 불가(근거 없음), 현행 유지. 필요한 근거 = 도입 전후 주문 수, 기간, 표본.
- 한계: 모의 투표, ①②는 자료 없이 일반 지식 판단. 2차 미실시(시행 전). 마무리: ①②를 시작할지, 배달비를 계속·변경·중단 중 무엇으로 할지 알려 주세요.

## 예시 3. 내용 없는 안건

요청: "예약 문자 문구 바꿀까?" → 투표하지 않고 "결론: 채택 후보 0, 조건부 0, 보류·기각 0, 판단 불가 0, 내용 요청 1 (모의 투표)." 이어서 현재 문구와 바꾸려는 문구, 그리고 이 문구가 코드 파일에 적혀 있는지 관리 화면에서 바꾸는지 쉬운 말로 묻는다.
