# 드문 경우

본문 규칙은 그대로 적용하고, 아래는 해당할 때만 덧붙인다. 충돌하면 이 파일이 우선한다.

## 이미 적용된 안건(소급)
- 1차는 "해당 없음(소급)"이고 관찰 데이터로 2차만 평가한다. 순위표 기준은 "소급"이다.
- 상태 해석: 채택 후보=계속, 조건부=조건부 계속, 보류·기각=중단 검토. 판단 불가는 근거가 확보될 때까지 현행 유지가 기본이다.
- 관찰 데이터가 없으면 일반 지식 투표를 하지 않고(본문 기권 규칙보다 우선) "판단 불가(근거 없음)"로 두며, 필요한 근거를 7번 항목에 쓴다. 관찰 데이터가 다루지 않는 차원(예: 소통 품질)도 일반 지식으로 투표하지 않고 필요한 근거에 적는다.
- 시범 계획은 "계속 시행할 때의 보완 계획"으로 쓰고, 마무리 질문은 "계속·변경·중단 중 무엇으로 할지"로 바꾼다.

## 안건 6건 이상
- 요약 형식을 쓴다. 2차는 적용 가능한 채택 후보·조건부와 차단급 재현 확인부터 시도한다.
- 25건 이상은 전 안건을 요약 형식으로 먼저 투표한다. 순위표 순서로 상위 12건(12위 동률 포함)은 요약표 아래 "상세" 블록에 안건별로 검사 주장·현행 변호를 한 줄씩 쓰고(25건 이상의 요약표 쟁점 칸에는 검사·변호를 쓰지 않는다), 나머지는 요약표 한 줄로 끝낸다. 판결은 상위 12건만 쓰고 13위 이하는 요약표 상태가 판결을 겸한다. 2차는 상위 12건 중에서만 시도하고 나머지는 "2차 미실시(1차 요약만)"다. 단 차단급이 붙은 코드 안건의 재현 확인은 순위와 무관하게 시도한다. ID가 Z를 넘으면 AA, AB로 이어 쓴다.
- 기각·전원 반대 안건의 이유는 "× 8명: 같은 이유"로 묶는다.

## 읽기 전용·파일 열람 불가
- 사용자가 지정한 읽기 전용이든("수정하지 마", "분석만") 도구가 막혀 있든 쓰기 불가로 본다. 2차는 "2차 미실시(읽기 전용)"이고 결함을 직접 고치는 작업은 하지 않는다. 반영도 하지 않고 권고만 낸다.
- 실행해야만 확인되는 재현 절차는 미확인으로 처리하고, 정적 검색은 1차 근거로 쓴다. 사용자가 붙여 준 줄은 열람 불가여도 인용으로 인정하되 "(미확인)"이며 원본 확인을 요청한다.

## 비코드 관찰 데이터
- 관찰 데이터는 기준선·기간·표본 수가 있는 지표·로그·설문이다. 설문은 응답 수·기간·기준선(전체 대비 응답 비율)이 있으면 인정한다. "불만이 늘었다는 느낌" 같은 체감 증언은 쟁점란에만 적는다.
- 기준선·기간·표본 수 중 둘 이상이 없거나 주어지지 않으면 관찰 데이터로 보지 않는다. 인정할 때도 세 값을 한계에 적는다.

## 영어 요청
- 요청 언어로 쓴다. 용어: 채택 후보 Approve candidate, 조건부 Conditional, 보류 Hold, 기각 Rejected, 판단 불가 Undecidable, 차단급 Blocker, 차단급 미확인 Unverified blocker, 2차 미실시 Round 2 not run, 1차 Round 1, 2차 Round 2, 소급 Retroactive, 기준 Basis, 내용 요청 Request for content, 결론 Conclusion, 판결 Verdict, 시범 계획 Pilot plan, 쟁점 Issues, 기권 Abstain, 모의 투표 Simulated vote, 머리말 Preamble, 검사 주장 Prosecution, 현행 변호 Defense, 유효표 Valid votes, 충돌 탈락/합침/폐기 Dropped/Merged/Withdrawn, 필요한 근거 Evidence needed, 일반 지식 판단 General-knowledge vote.
- 결론 문형: "Conclusion: Approve candidate N, Conditional N, Hold/Rejected N, Undecidable N (simulated vote)."
